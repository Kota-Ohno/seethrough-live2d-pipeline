# リギング前の標準作業フロー

人型キャラクターの反復制作で得た知見を、別のデザインにも使える工程へ整理したもの。特定モデルの座標、マスク、配色は含めない。数値処理の再現性と、意味領域・外観の正しさを別々に扱う。

この文書は作業手順であり、記載した全工程の自動ツールが本リポジトリに実装済みという宣言ではない。既存スクリプトはREADMEの対応範囲を確認して使用する。未実装工程は環境に合う手段を選び、実行方法を記録する。

## 最初に決める境界

- 制作対象、納品物、解像度、リギングまで含むかを明記する。
- 元絵・承認済み正本は読み取り専用の扱いにし、変更は新しい候補へ保存する。
- ユーザはデザインと品質を判断し、担当者・エージェントがマスクや補修を行う。毎回ユーザに境界を描かせない。
- 部分承認はその範囲へ適用し、ほかの箇所を好みで再調整しない。
- 画像上の位置を示すときは「向かって左」「金色の目側」などを組み合わせる。指摘箇所が不明なら、修正前に切り出しで確認する。

## 1. 入力と状態を揃える

通常、閉眼、開口と必要な隠れ面を同じ姿勢・寸法で準備する。髪を除いた衣服、顔の下の首、前髪の下の顔など、後で露出する部分を見積もる。

入力ごとに用途、原寸、ハッシュ、生成・取得条件、採用／不採用を記録する。生成比較画像の承認と、分解素材へ反映した合成結果の承認は別。生成画像を丸ごと顔へ差し替えて局所修正を済ませない。

## 2. 高精細化を実行する

Real-ESRGANの実行ファイル・モデル、引数、終了コード、所要時間、入出力寸法・ハッシュを保存する。単なる拡大、ファイル名、別の正本の実行記録では、採用した補完画像の処理を証明できない。

正本と別に生成した羽根・触角・衣服などは、採用経路を個別に確認する。後処理で元画素を復元した部分や高精細化画像以外の補修画素がある場合は、その由来を明記する。画素の見た目を守るための復元を隠して「全画素が高精細化出力」とは呼ばない。

## 3. 分解結果を単体で検査する

See-through等の出力は完成品ではなく分割・隠れ面の候補。原画への可視画素再投影の前後で、同じ場所の素材を比較する。

確認項目：

- 髪に眼・肌、衣服に三つ編み、首に顎線や襟が焼き込まれていないか。
- 細い毛先、羽根、触角が切れていないか。透明な画素下のRGBと可視ノイズを区別する。
- 背景色の混入、ぼけ、穴、継ぎ目がないか。明色・暗色の両背景で確認する。
- 近不透明な画素をすべて削って数値上の合成誤差を減らすと、隠れた下地に穴が開く場合がある。

合成一致だけで領域の所有者を正しいとしない。疑わしい部分は、同じ状態で所有者候補だけを非表示にして原因を特定する。ただし眼のマスク依存は維持する。

## 4. 補修は所有者と目的を決めてから

修正前に「どのレイヤー」「どの範囲」「色／透明度／形のどれを変えるか」「変えないもの」を書く。数値処理は汎用化し、ROI・対応点・種領域・適用可否は画像別の明示的注釈へ分離する。

### 輪郭

色の補修と透明度の補修を分ける。細かなギザギザが眼周辺の補助レイヤーにあり、ぼけが下の顔にあることもある。一枚だけ直して完了としない。

形を変えずにぼけを減らすなら、まず元の透明度を基準にする。例として、0〜1の透明度aへ `a^p / (a^p + (1-a)^p)`（p>1）を適用すると、0.5の境界を固定したまま遷移を狭められる。ただし細線や影に一律適用しない。RGBの不変性と50%透明度マスクの不変性を別々に検査し、実表示も見る。この検査は全中間透明度や将来の変形の不変性までは保証しない。

明暗から輪郭を追跡すると、隣の髪を拾って肌がへこむことがある。形を保つ目的にはその方法を継続しない。処理の終端が可視部分に残ると局所的なぼけになるため、髪との交差点直前と端のつながりを原寸で見る。単純に範囲を広げる前に、どの輪郭を追っているか確認する。

### 隠れ面と色

同じ衣服を構成する複数パーツには、同じ登録済み補完画像と整合する支持領域を使う。一枚のマスク内だけ硬く置換すると、襟や袖に境界が残る。

色合わせ後に背景色の漏れが再発する場合がある。特に暗部は小さい色オフセットの影響が大きい。最終色処理後の素材を明暗背景で確認する。原画に存在する色を背景色と決めつけて一律除去しない。

## 5. 表情素材を分離する

眼は白目、全周の瞳、動くハイライト、固定の瞼の影、まつ毛、必要な周辺補正を区別する。視線XYで動くのは瞳とハイライト。白目と瞳には共通の固定影を適用し、開口マスクの重複適用による縁の変化を避ける。

眼周辺の補正は純粋なまつ毛とは限らず、肌・瞼・影を含み得る。孤立画像で髪に見えても、開眼・閉眼の正本との比較なしに髪へ移さない。

口腔、歯、舌、閉じた口を保持し、口の内部を肌色で埋めない。閉眼・開口の画像は端点参照であり、透明度の切替を完成したまばたき・口パクとは呼ばない。

## 6. 変更に比例した検証

1. 修正パーツ単体を原寸・拡大で確認する。
2. 通常と関連する表情・非表示状態を同じ切り出しで比較する。
3. 全身でバランスを見る。
4. 全画像で変更許可領域の外が一致するか確認する。
5. 対象外パーツのハッシュ・配置・可視性の不変性を確認する。

大部品の縮小一覧、小部品原寸、局所原寸のレビューを区別して記録する。「全身を見た」を「すべての毛先を原寸で確認した」に読み替えない。

視線は両眼／左のみ／右のみで端・中心を確認し、指定眼以外と開口外が変化しないかを見る。静止視線試験は連続まばたきの検証とは別。

二回同じ原因・方法で失敗したら、[失敗切り分け表](pre-rig-failure-routing.md)へ戻る。強度や範囲だけを延々と変えない。

## 7. 品質ゲートを設ける

候補を提示して承認を待つ。承認後は外観を固定し、修正がない状態の同じ確認を何度も求めない。承認待ちの間はドキュメント・再現確認など独立作業に限定する。

PSD書き出しが高コストなら、小さい視覚修正のたびに完成用PSDを再生成せず、原寸合成で判断を終えてからまとめて書き出す。ユーザがPSD自体の確認を求める場合はその指示を優先する。

## 8. PSDを実ファイルから検証する

配置・順序・可視性・原寸ラスタ・色プロファイル・眼の依存関係を保存し、書き出したPSDを実際に読み戻して比較する。保存前の画像との一致を、PSD読戻しと混同しない。

編集用の合成PSDと、未クリッピングの全周瞳を保持する取り込み用PSDは用途を明記する。取り込み後に必要なクリッピング設定を同梱し、設定前のはみ出し表示を完成表示と誤認させない。ネイティブCubism取り込みの実施有無も別に記録する。

## 9. 再現・引継ぎ

最終素材、対応するPSD、入力・レシピ・処理コード、ハッシュ、実行結果、依存バージョン、失敗試案と理由を保存する。作ったパッケージから新しい出力先へ実際に再実行し、結果を比較する。

証明の段階を区別する：

- 保存済み直前入力から特定の素材を再作成できる。
- 最終素材からPSDを再作成し、読み戻しが一致する。
- 生成・意味領域推論から全上流を再実行できる。
- 新しいPC、別デザインでも再現できる。

前二つの成功だけで後二つまで実証済みとしない。

引継ぎ入口は一つに固定し、最新素材・PSD・承認範囲・未完了事項へリンクする。旧ログの「最新」「完了」が現行の指示として読まれないよう、履歴と明示する。

## 次回を楽にする運用

- [チェックポイントテンプレート](templates/pre-rig-checkpoint.md)を開始時に複製する。
- 変更前に一行の仮説と変更禁止事項を書く。後から大量のログを読むより速い。
- 目視レビュー済み素材へハッシュを結び、未変更部分の検証を再利用する。
- 生成比較画像は方向決定に使い、素材へ反映した時は必ず原寸合成を確認する。
- 小さな修正は原寸切り出し→関連状態→全身→承認→PSDの順にする。
- 公開リポジトリへは汎用手順・コード・匿名化した例だけを置く。認証情報、個人パス、未公開画像やモデルは混ぜない。
