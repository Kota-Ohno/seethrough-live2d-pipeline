# リギング・実動作・紹介撮影で得た知見

2026-09-20〜21の月繭こよみ（Azure Expressive Motion）制作で得た記録。既存の[リギング前フロー](pre-rig-production-workflow.md)の後段として使う。ここに記した手法は一体での実施例であり、全工程の自動化や別キャラクターでの再現を保証しない。

## 到達点と証拠の範囲

- ユーザーは通常の顔トラッキングでの見た目を承認した。パラメータ端点の数値試験と実用上の外観承認は別に記録する。
- スカートに連動した足首の欠けは、修正後にユーザーが解消を確認した。
- 髪・触角・衣装の強調した揺れ、こめかみの補修、三つ編みの重力方向調整を経て、ユーザーはモデルを合格とした。その時点でも三つ編みの戻りの遅さは気になる点として残った。追加の物理調整を最終映像の合格と同一視しない。
- 背景・名前ロゴ付きの約63秒の実トラッキング録画を保存し、再生可能なMP4にまとめた。最終の切り出し・映像品質の判断は別の編集工程へ引き継いだ。仮編集を完成版として扱わない。

## 違和感を部品の所有者まで追う

「上下を向くと変」「髪だけ置いていかれる」などの言語化しにくい指摘は、まず同じ動きを再現し、顔幅、縦の厚み、髪の根元追従、まばたきを個別に見る。原因を一つに決めつけない。今回、顔が縮む感じと髪の追従を調整した候補は「かなり自然」と評価された。

| 症状 | 今回の原因・識別方法 | 再利用できる対処 |
|---|---|---|
| スカートが揺れると足首がちぎれて動く | スカート側に足首の重複描画が混入 | スカートを単独表示し、ブーツ側の正しい足首を残してスカートのメッシュ対象から重複部を除外する |
| 髪が動いても金色の目の左上に髪の断片が残る | 顔本体と推測したが、実際には上まぶた周辺素材に髪が残存 | 髪を隠し、顔・上まぶた・下まぶたを個別に確認する。見える場所と所有レイヤーを混同しない |
| 銀色の目の外側で肌の色が違う | 前髪に隠れていた、まぶた素材の肌色・影のパッチが露出 | 正面だけでなく右傾き、髪の左右端、閉眼で確認。上まぶた補修後も下まぶた側に残ったため追加補修した |
| 髪を振るとこめかみが荒れる | 隠れ面の不備と髪の変形が同時に見える | 髪の可動域を狭めるだけで完了とせず、露出した素材の所有者を補修する |

こめかみ補修では、位置合わせ済みの生成ソフトマットを対象素材のアルファへ適用し、RGBと必要な描線を保全した。上まぶた2層の変更時は42層中40層、追加の下まぶた補修時は直前PSDの41層が画素一致だった。ソフトマットは描線も柔らかくし得るため、原寸で目の線まで確認する。

PSD再インポート後は対応する素材が差し替わったこと、アトラスとSDKに反映されたことを確認する。テクスチャだけの補修なら、moc3・物理設定・頂点の不変性を別途比較できる。変形の問題と素材の問題を切り分けるための証拠になる。

## 大きく揺らすときの設計

揺れの大きさは、キーフォームの可動域、Cubismの物理出力、VTube Studioの部位別倍率の複数段で変わる。どの段を変えたか記録し、一律に倍率だけを上げない。下記の値は今回の例であり推奨初期値ではない。

- 顔周りの髪は「外へ跳ねる」に加えて、頬・顔にかかる方向の形を作る。根元と中央姿勢を保ち、先端だけでなく中間点の露出も確認する。
- 触角の大きな縦跳ねは、うなずき入力と縦方向のキーフォームを対応させた。先端の上下変位拡大、振り子長、加速度、出力倍率を別々に調整した。
- スカートは腰側、袖は肩側を保ち、裾・袖口に動きを付ける。揺れる部品に他部位の画素やメッシュが混ざっていないことを先に確認する。
- 三つ編みは最大頂点変位を約457pxから627pxへ広げた例がある。絶対ピクセル値は素材寸法に依存し、他モデルへそのまま移せない。

### 三つ編みの重力方向と戻り

頭を傾けたまま髪束が斜めに留まる問題は、物理演算の角度入力による持続的な偏りと、親デフォーマの回転を分けて調べる。今回は角度入力の重みを0にする調整の後、専用の重力補償デフォーマに頭Z・体Zの3×3キーを作り、頭の実回転約±25度と体の約±7.3度を相殺した。付け根の位置は頭に追従させる。

これは限定した姿勢範囲での回転補償であり、汎用の重力シミュレーションではない。頭・体の複合姿勢、付け根の連続性、物理演算による大きな揺れと共存するかを確認する。

「重力方向へ向く」と「入力停止後すぐ戻る」は別の要件。停止後に空中へ残る感じは、振り子の遅延・加速度なども含めて実映像で判定する。今回の後段では遅延0.75→1.0、加速度2.0→3.0へ追加調整したが、この数値を普遍的な改善方向として流用しない。

## 検証を三つに分ける

1. **構造・数値**：対象メッシュの三角形反転・潰れ、対象外の頂点差、テクスチャと物理設定のハッシュを調べる。足首修正では405姿勢を調べ、スカート以外の頂点差とブーツ移動が0だった。これはサンプル姿勢の証拠で、連続する全姿勢の保証ではない。
2. **保存と配備**：CMO保存、閉じて再読込、SDK書出し、VTS側の再読込を確認する。モデル名だけではなく実ファイルとハッシュを対応させる。検証レポートが修正前の版を指す場合は明記する。
3. **実動作の外観**：自然なトラッキング、極端な複合姿勢、入力停止後の落ち着き、閉眼・開口を映像で見る。ユーザーの実用上の合格範囲と、残る懸念を記録する。

motion3.jsonのパラメータ記録は動画ではない。保存時平滑化を0にしてもBezier補間が入る場合があり、「raw」というファイル名は生フレームの証明にならない。記録値の収束時間を、実際の画面上の物理収束時間として断定しない。

診断ではカメラ入力と待機モーションを分離し、終わったら元のカメラ・待機モーション・トラッキング消失時の設定へ戻す。診断用に物理出力を直接駆動して、実運用の入力に対する応答を確認したことにしない。

## 撮影は録画経路を先に確かめる

本番の演技を頼む前に、数秒の無動作テストを開始・停止し、新しいクリップの時刻・長さ・内容が正しいことまで確認する。今回、録画キーを送っただけで開始したと思い込んだテイクは保存されず、一覧には以前の19秒クリップしかなかった。停止操作を送ったことも録画成功の証拠にならない。

- ファンクションキーのないキーボードを想定し、実際に押せるキーへ録画ショートカットを割り当てる。今回はCtrl+Alt+Rへ変更して録画可能になった。翅などの演出操作も同様に、使用可能なキーまたは画面ボタンを確認する。
- VTSが別ウィンドウの背面にある状態と最小化を区別する。カンペを前面に置く実際の配置で短く録画し、映像が動き続けることを確認する。「背面でも常に録れる」と環境を越えて保証しない。
- カメラ追従が止まったら、トラッキング、診断用待機モーション、消失時フリーズ、フォーカスやキャプチャ方式を切り分ける。
- 透かし、半透明の操作ボタン、カーソル、黒帯を確認する。今回の録画にも右端の丸いUIが写り、仮編集でクロップした。頭・触角・翅・足・ロゴを切らない余白を確保する。
- 日本語ロゴは装飾と別に漢字の字形を検査する。「月繭」の「繭」は生成案で誤りがあり、修正版を実際のVTSアイテムへ入れ替えた。

### 非同期チャットを秒単位のカンペにしない

エージェントが「次の動作」を逐次送信する方式は、ツール待ち・通信・ユーザーの読取りにより間がずれる。今回はユーザー自身が撮影する方式に切り替えた。一覧を先に渡し、本人のペースで演じてもらい、エージェントは事前確認と撮影後の編集を担当する。

動作表の例：

1. 正面で静止、まばたき2回、軽い口パク。
2. 左を向いて約1秒ため、少し勢いを付けて正面へ戻る。
3. 髪・触角・三つ編みの余韻を見るため約2秒待つ。
4. 左へ傾ける、正面、右へ傾ける、正面。
5. 小さく2回うなずく。
6. 翅を開いて保持し、閉じる。
7. 軽い口パク、最後のまばたき、約2秒静止して録画停止。

目安の尺より自然な動作と揺れの余韻を優先する。パラメータ端点の機械的な往復は診断用とし、紹介動画には本人の自然な動きを使う。切り出しでは開始前のためと戻った後の減衰を残し、静止画の一覧だけでテンポや戻りを合格にしない。

## Steam録画を扱う際の実施例

今回の保存物は、クリップ配下のMPD、映像・音声それぞれのinitセグメント、連番m4sだった。録画の最終更新時刻と全セグメントの存在を確認してから処理する。保存先や命名は固定仕様と仮定しない。

使用した同梱FFmpegはMPDを直接開けなかったため、作業用コピーでストリームごとに `init-streamN.m4s`、続く `chunk-streamN-00001.m4s` 以降を番号順にバイナリ連結し、映像と音声を個別の入力としてMP4へ再多重化した。この方法は今回の互換性のある断片で動いた回避策であり、任意のDASH素材・欠落した断片へ適用しない。元クリップは保持する。

復元した全尺は約63秒、3816×2030、HEVCだった。配布用はH.264など再生先に合った形式を別ファイルへ書き出し、全尺素材を残す。FFmpegは配布ビルドで機能が違い、今回のビルドには `drawtext` がなかった。フィルター・エンコーダの有無を先に確認する。解像度変更では縦横比・ピクセル比と色域変換も確認する。

- 症状、実際の所有レイヤー、採用した修正、不採用の方法。
- CubismとVTSの両方の倍率、入力割当、物理設定、診断後に戻した設定。
- 数値検査の対象版・姿勢範囲と、映像確認・ユーザー承認の範囲。

公開リポジトリには汎用手順と検証の限界を残し、個人の絶対パス、SteamアカウントID、認証情報、未許可の素材や録画は含めない。実行環境のGUI操作権限はその時点のツールで確認し、別タスクへの引継ぎで自動的に継承されたと仮定しない。
