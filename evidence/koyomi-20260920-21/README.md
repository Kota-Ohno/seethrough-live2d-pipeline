3つのプロジェクト内の保存先から、750ファイルを一覧化し、213件の記録を収録した。gzip圧縮後は約3.7MB。元データは変更していない。

- `deliverables`：今回の成果物フォルダ。数値検証、表示確認、作業状態、ユーザー評価、納品時READMEなど。
- `scratch`：今回の作業フォルダ直下。こめかみ素材、マット、PSD、アトラス位置の中間レポートなど。
- `native-stage`：今回の制作で使用した既存リギング段階の直下。顔・体・目・髪・触角・衣装のCore監査、物理設定、保存・再読込の記録など。

ルート単位の役割は保持し、個人の絶対パスは除いた。全身画像・顔の画像・録画・モデル本体・ソースコードなど506件、VTSの個人設定とmotion3曲線31件はメタデータのみ。大きいCore監査JSONも内容を省略せず収録した。作業中の別タスクやOS全体のログ、アカウント設定、完全な会話履歴は収集していない。

形式と検証方法は[観測記録の仕様](../README.md)。読み始めるには [index.jsonl](index.jsonl)、収録範囲は [inventory.jsonl](inventory.jsonl)、完全な匿名化済みpayloadは [records.jsonl.gz](records.jsonl.gz) を使う。

## 読み方

1. `index.jsonl` のpathで症状・部位を検索する。`ankle`, `temple`, `braid`, `head-volume`, `runtime-stop`, `cheek` など。
2. record_idで圧縮JSONLから該当payloadを取得する。同名ファイルが複数sourceにある場合、source_sha256を比較する。
3. payload内の対象moc3ハッシュ・サンプル数・未検証項目を確認する。別版の成功結果を現在版へ移さない。
4. 次の試行では原因仮説・変更値・比較対象・結果・残る問題を新しいファイルへ記録し、別スナップショットとして追加する。

`verification-status.json` や過去のREADMEに未完了と書かれていても、後のユーザー承認と矛盾するからといって消さない。どの版をどの試験で確認したかの記録である。ユーザーが最終モデルを合格とした会話上の判断は[知見文書](../../docs/rigging-runtime-recording-lessons.md)にあり、全ての過去ログを更新するものではない。

## 観測できていないこと

- 全ツール呼出しの完全なトランスクリプトや、実際のGUI入力時刻はこのアーカイブにはない。
- mtimeはコピー・再保存でも変わり得る。イベント時刻がpayload内にない場合、厳密な時間順は未確定。
- 数値試験は外観の保証ではない。平滑化・Bezier補間を含むパラメータ記録は生動画の代わりにならない。
- 収録時点で紹介動画の最終編集は別タスクで進行中。仮編集や投稿文案の存在を公開済み・完成済みの証拠にしない。
- 文字列匿名化で絶対パスに続く文脈も失われる場合がある。redactionsがあるrecordでは元ファイル参照が必要になり得る。
